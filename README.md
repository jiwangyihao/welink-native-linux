# WeLink Native for Linux

非官方、实验性的 WeLink 桌面客户端原生移植工程。原生接口层、Linux 集成、构建工具和测试源码以 **MPL 2.0** 开源。

这不是华为官方 Linux 发行版，也不是新的 Web 聊天外壳。项目在 Linux 上实现原客户端使用的原生接口，并适配既有 Electron 前端。商业客户端、厂商 SDK、品牌资源和用户数据不包含在本仓库或本项目的公开更新包中。

## 代码与能力边界

- `LoginSecurity/`、`HttpBridge/`：登录、设备身份、TLS/HTTP 桥接。
- `MessagingFiles/`、`Contact/`：IM 传输、编解码、加密数据库、联系人、离线文件与桌面工具。
- `Conference/`：会议管理、媒体/窗口/权限适配及本地原生处理代码。
- `ImportExport/`、`Support/` 和根目录 C 文件：存储、导入导出和辅助接口。
- `NativeIntegration/`：实际 Electron 主进程/渲染进程桥接，不以成功空实现替代缺失功能。
- `NativeBuild/`：依赖获取、编译、原包补丁重建、镜像完整性和旁路更新工具。

当前验证基线是 HIT 定制的 WeLink 7.47.6 前端及 Electron 22.3.26 / Node 16.17.1 **Linux ia32 ABI**。已在 x86-64 GXDE/Debian 环境运行；不要把它理解为任意上游版本、ARM 或原生 Wayland 均受支持。会议服务的账号资格、服务端授权和真实会议质量不由本项目保证。

### Bash、星火常用 DEB 与 APM

r45.18 的发布构件包括 `cn.edu.hit.welink.native_45.18-1_amd64.deb`（标准 Debian/星火格式）和 `cn.edu.hit.welink.native.apm_45.18-1-apm_amd64.deb`（真实 APM 容器包）。提供这些格式不表示已获星火商店上架审核；实际可用版本以发行页的稳定版标记和签名清单为准。

复制执行的入口是 Bash，不需要手动调用 Python 安装器：

```sh
curl -fL --proto '=https' https://github.com/jiwangyihao/welink-native-linux/releases/download/r45.18/install.sh -o install-welink.sh
bash install-welink.sh
# 或者选择已安装 APM 的系统：
bash install-welink.sh --apm
```

脚本以普通用户运行，先校验 Ed25519 发布签名、包大小和 SHA256，再仅提权调用 APT/APM；`--verify-only` 只下载验证，不安装。初始脚本通过上述 HTTPS 地址获取；签名保护后续软件包，并不替代对脚本发布者的信任。
APM 安装会把已验证的软件包移到 `/home` 下经过所有权与权限检查的私有 HOME 暂存目录，避免容器无法读取主机 `/tmp`；成功或失败退出时均清理暂存文件。

**这些是带预编译原生组件的安装引导包，不是商业客户端的离线重打包。** 首次启动会明确请求上游使用授权，获取并校验约 307 MB 固定输入后组装完整镜像，不在用户机器上编译。可通过 `welink-native-setup` 指定同散列的合法离线输入。普通包按 Debian 13／GXDE 25 的 amd64、Python 3.11+、ia32 glibc 2.41+ 基线提供；APM 使用 Trixie 基础环境，不要求旧宿主升级 glibc。启动器不追加全局 `--no-sandbox`，请求沙箱隔离的窗口使用嵌套用户命名空间；但旧前端的 Node-integrated renderer 不具备 Chromium renderer 沙箱保护，不能据此宣称整个客户端已沙箱化。

包管理器管理系统侧引导器与公共组件，用户镜像由客户端签名更新维护。安装脚本不启动应用、不修改现有资料或默认关联；移除/清除软件包会保留用户镜像、资料和备份。APM 使用独立的 `~/.local/share/hit-welink-native-apm/profile`，不会自动导入或覆盖普通原生版资料。


本项目使用独立的原生构建版本 `r45.x`，与上游客户端版本分开。Linux 的“检查更新”查询本仓库的原生稳定版；用户选择安装后，由内置流程验证发布签名和当前基线，下载正确的增量包、显示实际进度，在正常退出后切换并重新启动。**不会下载/执行 Windows `.exe`，不会执行未验证的网络脚本，也不会覆盖运行中的镜像。** 网络失败不等于“已是最新版本”。

r45.10 起，长发布说明只显示有界预览，避免把原生对话框按钮挤出屏幕；完整内容通过发布页查看。

r45.11 修正共享 HTTP 脚本在真实页面加载时的模块路径；r45.9 / r45.10 因启动回归已标记为预发布，不再参与稳定更新选择。

更新先准备独立镜像，退出后备份资料、激活并等待新版本真实就绪；失败时恢复旧入口与资料备份。所需的沙箱操作可能触发系统授权，整个安装器不会以 root 运行。旧版首次迁移及离线恢复仍可使用发布页中与基线匹配的安装器；这不是日常更新必须手动执行 Python 的要求。拒绝授权、取消退出或校验失败都不能被显示为更新成功。

公开应用资产只含本项目代码/原生构件、签名及校验元数据和最小 copy/literal 增量，不是完整商业客户端。另提供保留原有许可与对应源码出处的开源 Electron 运行时构建依赖。商业原版、模型或 SDK 由获取脚本从合法上游取得或由用户明确提供，不能通过改扩展名或套用本项目许可证来分发。

## 构建

见 [完整构建说明](docs/BUILD.md)。构建入口负责获取并验证固定输入、解包原版、编译原生实现与 FFI、重建适配文件，并执行 **prepare → 编译本镜像校验器 → finalize**。不会要求开发者机器上的隐含路径，也不能用另一镜像的校验器混用。

确认有权获取和使用上游 HIT/Huawei 输入后，在满足文档中的系统前置条件的干净检出目录运行：

```sh
python3 NativeBuild/full_build.py \
  --work "$PWD/.work/full-r45.18" \
  --cache "$PWD/.inputs/full-build-archives" \
  --build-id hit-native-linux-ia32-r45.18 \
  --accept-vendor-terms
```

`--work` 必须是新目录；下载缓存只按固定散列复用。无法联网时可按文档提供同散列的合法原始文件，不能拿其他版本或空目录冒充。

定制 Electron 可使用本项目发布的、已固定散列的开源运行时依赖；另保留从源码构建运行时的路径。使用预构建依赖不等于从零编译 Chromium。厂商输入和私有生成物留在工作目录，不提交商业资源、账号资料或提取出的白盒表。

## 验证

测试分为纯源码/协议测试、原生公开 ABI 回归、需要指定原始资源的隔离 Electron 场景，以及实机验收。没有原始资源或设备授权时，不能把缺失前提记作通过。CI 不使用工作账号或真实会议。

最近的本地基线验收覆盖了加密数据库查询、IPv4/IPv6 本地 TLS、窗口/协议唤醒、图片剪贴板和会议退出回执。生产企业会议、真实音视频质量、全部会话类型及每一种桌面合成器仍需各自验证。不要从一次无错误日志推导“所有功能完成”。

r45.17 的隔离回归另外覆盖当前固定 WebRTC 消费者、真实音频输出 API 的完成/拒绝、文件复制错误传播、ZIP/ZIP64 完整性与原子替换一致性、超过 2 GiB 的有界内存复制和压缩，以及 renderer 崩溃/导航/关闭失败后的恢复与浏览器令牌清理。原生 X11、访客语音、自定义背景和报告路径使用合成输入与本地服务验证；不表示真实企业会议授权、硬件媒体质量或官方举报已经受理。网络变化仍显式返回错误，不以静默重试或伪造成功掩盖。

r45.17 已在 GXDE/X11 客户机的现有原生资料上完成签名升级、私有备份和真实消息页就绪验收；失败回滚也已实际验证。就绪检查要求原始 IM 组件可见且非空，不再误依赖旧占位节点或单独承载页；仅有消息路由、空容器或隐藏内容仍不能通过。该结果不代表所有账号、会议与桌面环境均已验收。

r45.18 恢复原版启动遥测的非阻塞通知语义，避免未返回的埋点请求卡住首次隐私提示；异步错误仍可观察。首次使用的就绪检查要求原始隐私正文、“同意”和“不同意”控件同时可见并稳定，不会代替用户同意条款，也不会伪造已登录账号。

r45.18 已在 client 完成现有原生资料的签名升级和真实消息页就绪；普通 DEB 与真实 APM 包均完成隔离 HOME 首启。APM 另外验证了长 HOME 下的冷／暖激活、主进程 user/mount/PID namespace 隔离，以及真实 renderer 的嵌套 PID namespace、`NoNewPrivs=1` 和 `Seccomp=2`，没有代替用户同意隐私条款。

当前源码的媒体授权处理会复用同一浏览器会话内已允许的权限，并合并同类并发请求，避免麦克风／摄像头同时请求时重复弹出全范围授权。拒绝后仍可显式重试；跨来源、子框架和旧会话的迟到结果不会获得授权。`Conference/verify_media_permissions.js` 使用暂存的原生模块目录（`WELINK_TEST_NATIVE`）验证这些决策与生命周期边界，不访问设备或真实会议，不代表硬件采集或双端媒体质量已经通过。

离线文件提前续期失败时保留尚未到期的访问令牌，原有效期不延长；到期拒绝下载，但独立的刷新令牌续期仍可完成。`MessagingFiles/analysis/onebox_native_validation.py --renewal-only` 的隔离 HTTPS 回归覆盖刷新失败、过期拒绝以及 600 秒／短期令牌续期。r45.19 已在现有 GXDE/X11 资料目录完成此前失败的 Windows→Linux 文件下载，接收文件的长度与 SHA256 均与源文件一致。该实测不覆盖长时间挂起恢复；生产环境当次刷新失败的 HTTP／传输原因未被日志记录。

摄像头背景处理守卫保留 HRTC `removeTrack` 同步移除轨道的语义，再等待发布与背景清理完成；不再让调用方的同步移除循环反复看到同一轨道。真实 SDK 回归验证了立即移除及发送轨道释放，r45.20 实机也完成了 `/dev/video0` 开启、Windows 对端画面接收、明确关闭操作和设备释放。隔离回归使用原镜像的只读私有副本，并只调整该副本的可读性，不改原镜像权限。这些结果不等于音视频质量已全部验收。

r45.21 修正原始共享策略转发时的 `Meeting$Share` 配置键，避免已知跨企业会议的拒绝值被丢弃后变成允许。真实消费函数回归覆盖跨企业拒绝／允许、匿名策略和未知企业拒绝；旧产物会在拒绝用例中失败。当前固定 WebRTC 集成尚无经过核实的企业归属映射（`NO_VERIFIED_WEB_TENANT_RELATION_FIELD`），Linux 主动共享仍按安全策略拒绝；该键修复不代表屏幕共享已通过实机验收。

仍需注意：Electron 22 / Node 16 已过时；目前固定支持的上游、ia32 ABI 和 X11 桌面范围有限。新的上游版本、ARM、原生 Wayland、实际会议授权及媒体质量都需要各自验证，不能由“能构建”或“能更新”推导为已经支持。
